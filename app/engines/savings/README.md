# 예적금 엔진 계층 계약

예적금 흐름은 각 계층이 자기 입력만 읽도록 분리한다.

| 계층 | 입력 | 출력 | 하지 않는 일 |
|---|---|---|---|
| Repository | DB 연결, 기준일 | `ProductCandidate` 원천 데이터 | 금리 변환, 가입 판정, 계산 |
| Product Rule Pack | 상품명, 사용자 가입조건 사실 | `PASS` / `FAIL` / `UNKNOWN` | 이자·만기금액 계산 |
| Normalizer | `base_data`, `option_list`, 상품 구분 | 비율 금리·개월 단위 옵션, 명시적 오류 | 사용자 정보 조회, 정책 추정 |
| Adapter | Rule Pack handoff, 세율·우대확률·납입시점 | 완전한 `SavingsCalculationInput` 또는 `UNKNOWN` | DB 조회, 가입조건 재판정 |
| Calculator | 옵션 하나의 완전한 계산 입력 | 원금·세전이자·세금·세후 만기금액·연환산 세후수익률 | 후보 비교, 목표일 필터 |
| Evaluator | 계산 결과, 목표일·안전성·시장 비교범위 | 적격 여부, 점수와 구성요소 | 상품 원문이나 DB 조회 |
| Portfolio | 적격 평가 결과, 납입한도, 월·일시금 예산, 기관별 기존 예치액, 서비스 가중치 | 최대 3개 상품의 납입액·예상 만기액·미배분액·위험지표 | Rule Pack 재판정, DB 조회, 예금과 적금 예산 혼용 |

## 단위

- 금액: 원 단위 `Decimal`
- 공시 원천 금리: 퍼센트 숫자 (`3.2`)
- 엔진 금리·세율·확률: 비율 `Decimal` (`0.032`)
- 기간: 개월 정수
- 적금 납입 시점: `BEGINNING` 또는 `END`를 호출자가 명시

`expected_annual_rate`는 우대조건 달성확률을 반영한 세전 공시금리 기대값이다.
상품 점수의 수익률 항목에는 기간이 다른 상품을 공정하게 비교하도록 세후
현금흐름에서 계산한 `annualized_net_return_rate`를 사용한다. 적금은 월 납입
현금흐름의 IRR을 구한 뒤 연 실효수익률로 환산한다.

필요한 값이 없거나 해석할 수 없으면 0으로 대체하지 않는다. 가입조건은 Rule
Pack의 상태를 유지하고, 계산 입력 부족은 Adapter가 `UNKNOWN`과
`missing_inputs`로 반환한다. `extra_rate_info`처럼 표준 금리 옵션 밖의 방식도
원문을 보존하고 별도의 `UNKNOWN` 결과를 내므로 지원하지 않는 옵션이 조용히
누락되지 않는다.

## 포트폴리오 배분

포트폴리오 엔진의 근거는 공식 설계안 §12.1·§25와 역할분담 문서 §9.2다.

- 적금: `monthly_savings_budget` 안에서 월 납입액을 배분한다.
- 예금: `lump_sum_budget` 안에서 일시예치금을 배분한다.
- 두 예산은 시간 단위가 다르므로 합산하거나 서로 전용하지 않는다.
- 같은 상품의 기간·금리 옵션은 동시에 여러 개 선택하지 않는다.
- 상품별 최소·최대한도, 금융회사별 예금자보호 한도와 최대 3개 제한을 지킨다.
- 완전 배분이 불가능하면 가능한 금액만 `PARTIAL`로 반환하고 미배분액을 밝힌다.
- 만기위험·기관집중도·유동성 패널티 가중치는 공식 고정값이 아니므로
  `SavingsPortfolioPolicy`에서 명시한다.
- 포트폴리오가 최종 금액을 정한 뒤
  `revalidate_savings_portfolio_policy()`가 같은 기준일의 상품 Rule Pack을
  재실행한다. 최종 정책검증이 PASS인 배분안만 종합추천 계층으로 전달한다.

MVP는 후보 수가 작고 최대 선택 수가 3개이므로 가능한 상품 조합을 결정론적으로
탐색한다. 상품 수가 늘거나 정수 단위·복잡한 조건 최적화가 필요해지면 역할분담
문서 §9.3에 따라 OR-Tools 기반 구현으로 교체할 수 있다.
