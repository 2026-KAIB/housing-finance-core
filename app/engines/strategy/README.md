# 주택구매 전략 비교 엔진

## 목적

공식 설계안 §15~16에 따라 `자산축적형`과 `조기구매형`을 동일한 주택가격
시나리오와 전략점수로 비교한다. 이 엔진은 미래 주택가격이나 미래 대출한도를
예측하지 않는다.

```text
CombinedRecommendationResult ─┐
StressTestResult ──────────────┼─ services/strategy_comparison.py
호출자 주택가격·미래계획 ─────┘               │
                                              ▼
                               StrategyComparisonInput
                                              │
                                              ▼
                                  engines/strategy
                                              │
                                              ▼
                               StrategyComparisonResult
```

## 계층 경계

- `models.py`: 두 전략, 주택가격 시나리오, 점수와 결과 계약을 정의한다.
- `engine.py`: 시나리오별 자금충당 여부와 공식 전략점수를 계산한다.
- `services/strategy_comparison.py`: 종합추천·스트레스 결과를 순수 입력으로 옮긴다.
- 엔진은 DB, FastAPI, Rule Pack, 원천 상품 데이터를 직접 호출하지 않는다.

## 전략점수

```text
100 × (
    0.35 × 시나리오달성도
  + 0.25 × 구매후현금흐름안정성
  + 0.20 × 총금융비용점수
  + 0.10 × 목표시점적합성
  + 0.10 × 계획변경유연성
)
```

- 시나리오달성도는 `PASS 수 / 전체 시나리오 수`다. 하나라도 `UNKNOWN`이면
  달성도를 확정하지 않는다.
- 총금융비용은 두 전략 모두 확인된 경우에만 상대 정규화한다.
- 목표시점은 공식 문서에 세부 감점식이 없어 목표일 이내 `1`, 초과 `0`으로
  판정하며 실제 지연 일수를 함께 반환한다.
- 결측값은 0점으로 바꾸지 않는다. 확인된 가중치가 정책 임계 이상이면
  `PROVISIONAL`, 미만이면 `UNAVAILABLE`이다.
- 점수가 높더라도 달성 가능한 주택가격 시나리오가 하나도 없는 전략은 최종
  추천 후보가 될 수 없다.

## 금액 중복 방지

자산축적형의 자기자본은 다음처럼 조립한다.

```text
구매시점 자기자본
= 정책검증을 통과한 예적금 예상 만기액
 + 포트폴리오 만기액에 포함되지 않은 추가 축적자금
```

예상 만기액에는 이미 배분 원금과 이자가 들어 있으므로 현재 목돈을 다시 더하면
안 된다. 서비스의 `additional_accumulation_equity`는 이 만기액과 겹치지 않는
구매시점 자금만 받아야 한다.

## 현재 의도적으로 UNKNOWN인 값

현금흐름 엔진 개발 전에는 자산축적형의 구매 후 현금흐름 안정성을 자동 생성하지
않는다. 미래 대출한도·상환액·총비용과 계획변경 유연성도 근거가 없으면
`None`으로 유지한다. 이런 경우 임시 선두는 표시할 수 있지만 최종 추천은
확정하지 않는다.
